# Sub-fetta 1.5.A — Pivot 3 (eurouter default) + CLI puro multipiattaforma

## Problem

Sprint 1 era stato sviluppato e validato su NFR-1 "locale mandatory" (Ollama on-device, no cloud) e bundle `.app` macOS (doppio click + osascript + drag&drop). Post-Sprint-1 emerge che Denis non ha hardware sufficiente per Ollama (Qwen 3 36B MoE = ~23 GB di modello). Stefano Fiorina (cliente) approva il pivot a eurouter cloud EU-GDPR come provider default. In più, il bundle `.app` introduce verbosità inutile vs `labnexus.command` 2-righe. Refactor pre-handoff Denis necessario.

## Solution

Pattern di refactor in 11 step decommissioning:
1. Bug file di gate cloud aggiornati a `intentional_deviation_post_pivot_3` (mantengono storia, status semanticamente corretto)
2. Funzioni gate (`requireLoopbackOrCloudGate`, `isLoopbackHost`, `ErrEurouterGateMissing`) rimosse da `provider.go` (~50 LoC)
3. 10 test associati rimossi da `select_test.go` (~110 LoC) — pattern Sprint 1+2 "static-analysis BDD" copre il fatto che siano davvero spariti
4. BDD `helpers_test.go::buildEnv` non setta più `LABNEXUS_ALLOW_CLOUD_PROVIDER`
5. 7 profili shippati cambiati `provider: ollama → eurouter`
6. 4 scenari BDD del bundle `.app` eliminati da `motore-modo-interattivo.feature`
7. `scripts/labnexus.command` creato (launcher 2 righe + shebang + fallback `||` con feedback)
8. `scripts/build-mac.sh` ridotto da 113 a 22 righe (singolo `go build` cross-compile)
9. `scripts/build-zip.sh` ridisegnato per nuovo layout (stage temp + `zip -j` root files + `zip -r` cartelle)
10. Docs aggiornati (README, USER-GUIDE, DEV-GUIDE, CONTEXT, Makefile)
11. Filesystem cleanup: `internal/bundle/` package + `labnexus.app/` directory eliminati

Validation: BDD static-analysis (11 nuovi scenari su `sprint1.5-A-pivot3-cli-puro.feature` + esteso `steps_test.go` con 7 step phrasings `sprint15a_*`).

## What Worked

- **Pattern static-analysis BDD (riapplicato da Sprint 1+2)**: assertion su contenuto sorgente, niente subprocess di build. CI-friendly, zero side-effect.
- **Bug file aggiornati invece di cancellati**: lo status `intentional_deviation_post_pivot_3` con `deviation_at` + `deviation_rationale` esplicito mantiene la storia decisionale. Nessuna lesione audit.
- **Solution-leaning pacchetto deliverable**: il `labnexus.command` con fallback `|| { echo ... read }` aggiunto in review loop 2 ha aumentato la forgiveness (McKay) senza esplodere LoC.
- **Loop 2 review fix-all Claude-only** è stato efficiente (~45 min per 11 fix + 1 regressione + verify) nonostante l'esternalizzazione fosse degradata. La self-review aveva trovato tutti gli HIGH che importavano davvero.

## What Didn't Work

- **Sub-fetta 1.5.A /v-implement ha sottostimato il scope "documentation as code"**: aggiornati 5 docs (README, USER-GUIDE, DEV-GUIDE, CONTEXT, Makefile) ma il /v-review loop 1 ha trovato 5 HIGH doc-drift: `.pipeline/standards/02-project.md` (Layer 3) non era stato nemmeno toccato; e 4 dei 5 file aggiornati avevano residui obsoleti (es. README riga 3 in contraddizione con la sua tabella). **Lesson per il prossimo /v-implement post-pivot semantico**: dopo aver toccato la lista di docs nel plan, fai `grep -rn "<pattern obsoleti>" .pipeline/standards/ docs/ *.md scripts/` per audit completo.
- **Audit trail by-product (`locale: true` nei 7 frontmatter_default)** non era stato anticipato dalla spec né dal plan. È un caso classico di "il pivot semantico ha implicazioni nei marker generati dal codice, non solo nel codice stesso". Il review ha catturato in loop 1 → fix in loop 2 (rimossa chiave, audit silente preferito ad audit menzognero).
- **External reviewers degraded**: codex quota (atteso, evidenziato pre-flight), mistral + ollama timeout sul prompt completo (NON evidenziati dal preflight smoke a 15s — il prompt completo è di ordine 10× il smoke). Lesson: smoke != production-load. Per review futuri considera un secondo smoke più realistico (es. 30s con prompt 2× il smoke attuale).
- **state.json `current_fetta` schema strict**: avevo settato `"1.5.A"` (stringa) — vibbly/vobbly schema vuole int. Errore mascherato come `[REVIEW] SETUP ERROR: not a vibbly-managed project` (messaggio non diagnostico). Il CTO ha identificato il problema, non io. Lesson per me: quando i comandi vobbly falliscono con "not vibbly-managed", controlla SEMPRE PRIMA lo schema di state.json, non assumere project marker mancanti.

## Reusable Pattern

**Post-pivot semantico doc audit grep checklist** — vedi `.pipeline/skills/project/post-pivot-doc-audit-checklist.md` (creata in questo cycle).

Pattern: dopo qualsiasi pivot che inverte una decisione architetturale (es. locale→cloud, sync→async, monolite→split, framework-A→framework-B), il /v-implement non basta aggiornare i file menzionati nel plan. Bisogna anche:

1. Enumerare i pattern testuali obsoleti (es. "Ollama", "locale: true", ".app", "osascript")
2. Fare `grep -rn "<pattern>"` su `docs/ README.md CONTEXT.md .pipeline/standards/ scripts/`
3. Per ogni hit, valutare: aggiornare? marcare come storia? rimuovere?
4. Anche i marker by-product generati dal codice (frontmatter, headers HTTP, log labels) vanno auditati — l'inversione del pivot può rendere ENGANNOSO un marker che era veritiero

Costo: 5-10 minuti pre-/v-review. Beneficio: evita 5 HIGH findings di doc-drift catturati dal review (cui poi serve loop 2 per fixare).
