# Sprint 1.5.D — Output PDF + DOCX accoppiati

## Problem

Lo Sprint 1.5 era chiuso ma in produzione (smoke reale di Matteo su CAPABILITY A) sono emersi 5 problemi in cascata:

1. **Walk non-ricorsivo input** (FR-4 originale): il tool vedeva solo i file in root della capability, ignorava `Documento_da_revisionare/` e `Nuovi_Requisiti_Accredia/` con i file reali.
2. **PDF accoppiato all'MD** richiesto: Denis riceveva solo `.md`, ma per stampa/consegna formale serve PDF brandizzato.
3. **DOCX accoppiato** richiesto: L2 validation di Denis vive in Word (track changes, comments). PDF non lo permette.
4. **HTTP timeout overall** in eurouter tagliava lo streaming a 120s (modelli grossi tipo qwen3.5-122b a 8.7 tok/s impiegano 2+ min). Same bug già fixato per ollama, replicato qui.
5. **Fence wrapping LLM spurio**: Qwen3.5-122B emetteva l'intero output racchiuso in ` ```yaml ... ``` `, rendendo il MD un code block monospace nei viewer.

## Solution

**Walk ricorsivo** (commit `fb1ec90`): `filepath.WalkDir` con skip di `output/` (hardcoded `labnexusInternalDirs`) e cartelle prefisso `.`. `ParsedFile.Name` diventa path POSIX relativo (es. `Documento_da_revisionare/MQL_Rev03.docx`), così il prompt LLM preserva la semantica della struttura cartelle.

**Sanitize fence wrapping** (commit `7f106e3`): `stripFenceWrapping` in `internal/runner/sanitize.go` con euristica conservativa (prima riga ``` + ultima riga ``` → strip). Applicato in `streamAndWriteOutput` PRIMA di scrivere `.md`/`.pdf`/`.docx`.

**HTTP timeout** (commit `76c1e12`): replica pattern già documentato in `.pipeline/bugs/http-overall-timeout-tronca-streaming-llm.md` per ollama. `Transport.ResponseHeaderTimeout = p.Timeout` (TTFB only) + `Client.Timeout = 0` (body unlimited).

**PDF pipeline** (commit `7f106e3` + `8621b4d`): pivot consapevole dal custom renderer `goldmark+fpdf` (8 file Go, 600 righe) a `pandoc → typst` dopo bug visuali cumulativi (callout multilinea, H1 line-height, tabelle non impaginate, accenti italiani). Stack: pandoc 3.9.0.2 + typst 0.14.2, entrambi native Apple Silicon, scaricati in `dist/.../bin/` via `scripts/download-pdf-tools.sh`. Template `internal/pdf/template.typ` embedded via `//go:embed`, palette AICertus estratta da `labnexus.app/ecosistema/aicertus`.

**DOCX pipeline** (commit `3dba389`): pandoc-only (no typst, niente catena extra). Reference `internal/pdf/reference.docx` con design token applicati a XML interno (`word/styles.xml`, `header1.xml`, `footer1.xml`). Placeholders `{{CAPABILITY}}/{{PROFILO}}/{{MODELLO}}` sostituiti a runtime in `writeReferenceDocxWithMeta` (ri-zip in tempdir).

**Config gerarchy `[pdf]` e `[docx]`** (commit `7f106e3` + `3dba389`): tristate `*bool` per distinguere "non setted" da "false esplicito", `ResolvePDFEnabled(cli, job, master) bool` come funzione pura. Gerarchia: CLI `--pdf`/`--docx` > `_labnexus.toml` per-job > `labnexus.config.toml` master > default `false`. Master di default ON per tutte e 7 le capability post-Sprint 1.5.D.

## What Worked

- **TDD disciplinato in linea**: per ogni fix/feature ho scritto test rosso PRIMA di toccare codice (walk ricorsivo, HTTP timeout, fence wrapping, callout DOCX). Quasi tutti i test sono passati al primo colpo dopo implementazione perché il test guidava il design.
- **Smoke reale di Matteo + log produzione**: loop `produzione → log mostra problema → io scrivo test rosso → fix → smoke nuovo` molto rapido. Bug come "stream error context deadline exceeded" e "fence wrapping yaml" trovati guardando il log reale, non in test sintetici.
- **Pattern replication**: `ollama_streaming_unlimited_test.go` ha dato template diretto per `eurouter_streaming_unlimited_test.go`. Stesso problema, stesso fix, copy-adapt 10 minuti.
- **Pivot consapevole a pandoc+typst**: dopo 3 bug visuali in 1 ora sul renderer custom (callout multilinea, H1 line-height, tabelle), riconoscere che il custom rendering richiedeva troppi fix iterativi vs pivot a tool maturi. Decisione fatta esplicitamente con cost/benefit (single binary 10MB → 230MB con dist), trade-off documentato.
- **`//go:embed` per template assets**: template.typ + callout-filter.lua + reference.docx tutti embedded nel binary labnexus, niente file esterni richiesti, niente runtime path discovery per asset.
- **Config tristate gerarchica riusata**: il pattern PDF è stato copiato per DOCX in 15 minuti, con `ResolveDocxEnabled` come alias semantico di `ResolvePDFEnabled`.

## What Didn't Work

- **Sopravvalutazione del DOCX branding iniziale**: ho dichiarato "branded" dopo aver patched 10 occorrenze di un singolo colore. L'utente ha dovuto far notare che mancavano 9 elementi su 10 (header pagina, footer, accent borders, code bg, table fill, etc.). Lesson: prima di dire "branded", **confronto puntuale tokens PDF-vs-DOCX su tabella esplicita** (vedi 9 token nel commit `3dba389`).
- **API key cancellata per sbaglio**: ho sovrascritto `dist/labnexus.config.toml` con la versione root azzerando `eurouter_api_key`. Lesson: prima di copiare config in dist, **leggere il file esistente** e mergeare solo le nuove sezioni, non rimpiazzare il file intero.
- **MD del run 11:17 sparito**: ho promesso "ti rigenero il PDF dal MD esistente" senza verificare che il file ci fosse ancora. Era stato cancellato tra i run. Lesson: prima di promettere recovery retroattivo, `ls` del file.
- **Custom renderer ha richiesto pivot**: ho sottostimato il numero di edge case visuali in `goldmark+fpdf`. Avrei dovuto considerare pandoc già al momento della prima scelta (l'utente l'aveva suggerito esplicitamente nella valutazione iniziale, opzione 3). Lesson: quando l'utente menziona un'opzione "pesante ma mature" e tu raccomandi "pulito ma custom", **specifica i 3-5 bug visuali tipici** che il custom dovrà fixare nel corso del lavoro.
- **`make ship` ordine errato la prima volta**: `clean → test → ... → pdf-tools` invece di `clean → pdf-tools → test`. Tests fallivano perché clean cancellava `dist/bin/` e pdf-tools era ultimo. Lesson: quando aggiungi un nuovo step che produce file usati dai test, **deve essere prima dei test nella catena `ship`**.

## Reusable Pattern

### 1. Bundle binari external in dist + risoluzione runtime

Per Go cli-tool che richiede tool nativi non scrivibili in Go (pandoc, typst, ffmpeg, ecc.):
- Script `scripts/download-*-tools.sh` idempotente con cache locale `.cache/*-tools/` per i .zip/.tar download
- Estrae binari in `dist/<pkg>/bin/` accanto al binary principale
- Risoluzione runtime via `os.Executable() + "/bin/" + toolname`
- Fallback `findRepoDistBin()` per dev (cerca `dist/<pkg>/bin/` risalendo dalla CWD)
- Env override per test: `LABNEXUS_PANDOC_PATH`, `LABNEXUS_TYPST_PATH`
- `make ship` target con ordine: `clean → pdf-tools → test → vet → package`
- `build-zip.sh` include `bin/` nel zip + popola `dist/<pkg>/` cartella estratta pronta all'uso

Vedi nuovo skill `external-binaries-bundled-in-dist.md`.

### 2. Tristate config gerarchy CLI > job > master > default

Per qualsiasi feature opt-in con override multi-livello:
- Field `*bool` (non `bool`) per distinguere "non setted" da "false esplicito"
- Funzione pura `Resolve*Enabled(cli, job, master *bool) bool` — primo non-nil vince, fallback `false`
- CLI: `cmd.Flags().Bool("name", false, "...")` + `cmd.Flags().Changed("name")` per detection tristate
- TOML: sezione `[feature]` con `enabled` come `*bool` (BurntSushi/toml lo gestisce nativamente)
- Master attivo by default + per-capability override + CLI override massimo per-run

Estende skill `master-profile-config-inheritance.md` aggiungendo dimensione "per-job" + tristate detection.

### 3. Sanitize fence wrapping spurio LLM

Alcuni modelli (osservato Qwen3.5-122B) emettono l'intero output racchiuso in fenced code block (` ```yaml ... ``` `). Tutti i viewer markdown lo trattano correttamente come code block monospace, perdendo heading/callout/tabelle.

Detection conservativa Go-side:
```go
trimmed := strings.TrimSpace(body)
if strings.HasPrefix(trimmed, "```") && strings.HasSuffix(trimmed, "```") {
    // strip prima linea + ultima ```
}
```

Da applicare PRIMA di scrivere MD/PDF/DOCX nel runner. Pattern applicabile a qualsiasi pipeline LLM→MD→render multi-output.

Vedi nuovo skill `llm-output-fence-sanitizer.md`.
